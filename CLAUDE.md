# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this project is

**Koi 8×8** — an open-hardware 64-channel current-source driver / voltage-readout
controller, built to drive TiN thermo-optic heaters on photonic chips. One
RP2040 (Raspberry Pi Pico) motherboard controls up to **8 daughterboards** over
PCIe-style edge connectors; each daughterboard carries a DAC80508 (8-ch DAC),
an AD7193 (8-ch ADC), and 8 XTR200 current-source front ends — 8 boards × 8
channels = 64. The PC talks to the firmware over USB serial with a line-based
ASCII protocol (`ISETA`/`MEASA?` etc.); target publication is a HardwareX paper.

`hardware/*/production/` holds generated fab outputs (gerber zip, BOM,
positions, netlist) from the KiCad fabrication-toolkit plugin — regenerate them
from KiCad rather than editing by hand. `~*.lck` files mean KiCad may have the
project open.

## Commands

Firmware (run from `firmware/motherboard-test/`):

```bash
pio run                 # build (env:pico)
pio run -t upload       # build + flash over USB
pio device monitor      # serial monitor @ 115200
```

No working test suite. Host-side tools are in `firmware/motherboard-test/tools/`
(`koi_gui.py` — Tkinter 8×8 monitor GUI, needs `pyserial`; `cal_*.py`,
`sweep_*.py` — calibration/characterization scripts; CSVs there are bench data).

Paper (run from `paper/`):

```bash
make            # -> main.pdf (pdflatex + bibtex)
make clean
```

## Cross-cutting facts

- The device identifies as `KOI,8x8,fw1.1` (formerly `MOBO`); "device index" =
  daughterboard, global channel index `g = board*8 + channel` (0–63).
- Firmware reports the **raw ADC-pin voltage**; the host applies the 6:1 input
  divider (×6) to get the true heater voltage. This convention spans firmware,
  the GUI, and the paper — keep them consistent.
- The paper's Validation section (Section 8) awaits the Keithley 2400
  calibration campaign; `\todo{...}` markers in `main.tex` track missing pieces.
  Its architecture/protocol prose was transcribed from the firmware `CLAUDE.md`,
  so protocol or measurement-model changes should propagate there.
